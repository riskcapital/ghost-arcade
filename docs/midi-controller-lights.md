# MIDI controller lights

Settings → MIDI → Controller lights enables feedback for the current app session. Select an output or let Ghost Arcade match the selected input to an unambiguous output name. The output is independent of MIDI Clock. Ambiguous or missing ports require an explicit selection. A hardware profile may be selected manually when the operating system reports an unfamiliar name.

Supported profiles: APC40 mkII (5×8), APC mini mk2 (8×8), Launchpad X (8×8), Launchpad Mini mk3 (8×8), and learned note pads on other devices. Older APC/Launchpad models are not treated as these profiles. Feedback follows the selected deck or a fixed A/B deck, with separate layer and column pages. Layer 1 starts at the top-left of the physical grid. Empty cells are off, loaded cells dim, active cells bright, and queued cells blink yellow. A uses green and B blue. Disabled deck B is dark. A playing clip in another block does not light an unrelated clip at the same address.

With “Pads launch the displayed grid” enabled, unassigned grid notes launch the shown cells. Existing learned mappings take precedence. Releases retain the original deck/page address so switching pages while holding a Piano pad cannot leave it stuck. Learn and identify modes suppress grid launching. Learned clip triggers, VJ workspace, crossfader enable/cut, and block-selection notes have state feedback; arbitrary effect toggles are not yet covered. Generic LEDs use 0/20/127 and depend on the controller accepting note-velocity feedback. A channel-agnostic learned mapping sends feedback on channel 1.

Updates are coalesced per animation frame and only changed LEDs are sent. Software blinking uses a 250 ms half-period, independent of whether the controller receives MIDI clock. Disabling lights, closing the mixer, switching outputs/profiles, or normal app teardown clears the LEDs that Ghost Arcade owns. Hot-unplug cannot receive a final clear; reconnect redraws the full grid. A failed output stops sending until lights are disabled and enabled again. Forced process termination cannot perform hardware cleanup.

Enabling lights requests Web MIDI SysEx access for device setup. APC40 mkII enters host-controlled Live mode and returns to Generic mode on release. Launchpads enter Programmer mode and return to Live mode on release; use their MIDI port, not a separate DAW port. These are known exit modes, not restoration of an unknown previous hardware mode. APC mini mk2 uses note messages without a mode handshake. Settings retain profile/output preferences, but lights must be enabled each app session. Avoid having two applications drive the same controller surface simultaneously.

## Protocol sources

- [Akai APC40 mkII Communications Protocol v1.2](https://cdn.inmusicbrands.com/akai/attachments/apc40II/APC40Mk2_Communications_Protocol_v1.2.pdf): setup on pages 10–12; note assignment on pages 13–17; RGB channel and palette tables on pages 18–22. Grid notes 0–39 use primary-color channel 1. Host mode uses configuration 0x41; exit 0x40.
- [Akai APC mini mk2 Communications Protocol v1.0](https://cdn.inmusicbrands.com/akai/attachments/APC%20mini%20mk2%20-%20Communication%20Protocol%20-%20v1.0.pdf): page 2 pad diagram (bottom-left 0, top-left 56); pages 3–5 brightness and palette. Grid output uses zero-based channel 6 for full brightness; palette entries provide dim colors.
- [Novation Launchpad X surface protocol](https://userguides.novationmusic.com/hc/en-gb/articles/24001475492498-Controlling-the-Launchpad-X-surface): Programmer layout, static note feedback on channel 1, color palette, and mode guidance. Grid corners are 81/88 at the top and 11/18 at the bottom. [Programmer guide](https://downloads.focusrite.com/novation/launchpad-mk3/launchpad-x) supplies the device setup message.
- [Novation Launchpad Mini mk3 Programmer Reference](https://fael-downloads-prod.focusrite.com/customer/test/s3fs-public/downloads/Launchpad%20Mini%20-%20Programmers%20Reference%20Manual.pdf): pages 7–12 mode switch, grid layout and note feedback. Setup header uses product 0x0D; Launchpad X uses 0x0C. Command 0x0E selects Programmer (1) or Live (0).

## Validation and remaining acceptance

Automated tests exercise profile message bytes, note lookup, unambiguous port pairing, deck/page state, queued blink, change-only output, old-port cleanup, mode entry/exit, denied setup access, output failure, actual manager routing through simulated Web MIDI, learned-mapping priority, page changes during held notes, and disconnect/reconnect. These tests do not verify physical controller firmware, displayed colors/orientation, USB latency, or Windows driver naming. Physical acceptance on each named model remains required before advertising hardware qualification. The existing clock output is unchanged.

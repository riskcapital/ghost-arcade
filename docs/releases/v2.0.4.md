# Ghost Arcade 2.0.4

The in-app preview on Windows, a faster native renderer, and AI control.

## The editor preview works on Windows

Reported as a video playing on the output but not in the in-app preview,
fine in 1.9. It was never about the video: a clip that reaches the output
has already been found, decoded and composited.

In 1.9 the preview was the renderer, drawn by the browser. In 2.0 the core
renders offscreen and the composite is transported into the editor
viewport, and that transport only existed on macOS. On Windows the output
window showed the composite and the editor preview showed nothing, whatever
you loaded.

Windows now presents the preview from its own pump thread, paced by the
display rather than a JavaScript timer. The old arrangement could not hold
60Hz and slipped unevenly, delivering 15 to 27fps against a core rendering
a steady 55; the jitter, more than the average, is what read as stutter.
Measured 152.9fps on a 165Hz panel.

The vblank wait now happens off the Electron main thread. Previously the
thread that dispatches clicks, scrolling and window messages could sit
waiting on a lock held for a whole frame, several times a second, and a
minimised window could not be restored at all.

Where no presenter exists at all, the preview falls back to mirroring the
composite. It waits to see whether a presenter turns up before paying for
that, and releases it if one does.

## Native renderer performance

A reliability and performance pass across output correctness, shader and
pipeline retention, asset caches, allocation admission, command
backpressure, blocking work moved onto bounded workers, video memory and
timing, and device lifetime.

Measured on an Apple M1 Max at 1080p:

| Workload | Before | After |
| --- | ---: | ---: |
| 16 overlapping translucent layers | 28.1 | 43.3 |
| 16 layers and four composition effects | 18.9 | 26.5 |
| The same with two extra 1080p slices | 12.4 | 25.0 |

Renderer process CPU on a live Windows session went from 94% of a core to
22%, with the composite decode leaving the profile entirely.

## AI control

Ghost Arcade can host an MCP server, so a client such as Claude Desktop can
operate it: fire clips, move faders, launch columns, set tempo, and look at
the output to check the result. Off by default; turn it on in Settings,
OSC. It listens on this machine only and every request carries a token that
is reissued each time you switch it on.

The tools are built on the same control paths MIDI and OSC dispatch
through, so a model reaches whatever a hardware controller reaches. See
docs/mcp.md.
